# Web, UI, and blog integration audit — October 4, 2026

Status: open review backlog. Proposals are not implemented or approved decisions.
The review included current uncommitted work and local browser checks, including
a 390-pixel viewport. `npm run check` passed with 229 tests. See the
[project audit](../../../backend/docs/reviews/2026-10-04.md) for limits and sequencing.

## WEB-01 — P1: invalid calculator input produces a positive verdict

**Reproduced in the browser.** Clearing TX power passes `NaN` from
[NumberField](../../src/components/shared/widgets/Field.tsx) to
[computeLink](../../src/core/map/linkBudget.ts). Comparisons fail and the verdict
falls through to `strong`. The page displayed Strong link, NaN power/margin,
501 nodes costing $33,066, and the claim that one camera site costs more.

**Proposal:** keep editable text separate from validated numeric inputs; check
finite values and allowed ranges before calculation; suspend results while input
is incomplete. HTML min/max attributes alone do not validate application state.
**Acceptance:** empty, nonfinite, negative, and out-of-range input cannot produce
a positive verdict or misleading cost; valid input and unit switching still work;
cost comparison copy depends on the actual comparison.

## WEB-02 — P2: malformed URL fragments crash the page

**Reproduced in the browser.** Opening `/map#[` causes
[Page.tsx](../../src/components/layout/Page.tsx) to pass `#[` to querySelector, throw
SyntaxError, and show the error boundary. Reload retains the invalid URL.

**Proposal:** look up an element ID without constructing an unsafe CSS selector,
handle fragment decoding safely, and ignore unknown anchors. **Acceptance:**
special characters, malformed encoding, Unicode, and missing anchors do not
crash; valid deep links scroll correctly.

## WEB-03 — P1: a changed USB identity retains another node's history

**Reproduced at the protocol layer; physical port swapping was not tested.**
[serial.ts](../../src/core/nearby/transport/serial.ts) identifies ports by vendor,
product, and order. [session.ts](../../src/core/nearby/session.ts) resets nodeNum on
connect but retains history. [protocol.ts](../../src/core/nearby/protocol.ts) accepts
new myInfo while leaving that history intact. A new node number retained an old
temperature series in the isolated experiment. Hydration is also keyed by
transport ID rather than confirmed node identity.

**Proposal:** isolate telemetry and hydration by confirmed Meshtastic node number;
reset previous identity-specific state when a port identifies another node.
**Acceptance:** two identical USB devices can be reordered/replaced without
mixing histories, peers, or readings; the same node over Bluetooth and USB still
shares the correct persisted history.

## WEB-04 — P2: live network state has no shared data layer yet

**Inspected; incomplete feature.** [network.ts](../../src/core/content/network/network.ts)
declares an endpoint, but Map, NetworkMap, NodeTable, NodePanel, and counters use
static NODES/LINKS directly. Changing SOURCE alone cannot connect them to the API.
[Map.tsx](../../src/components/pages/Map.tsx) also uses Math.max on links, which yields
negative infinity for an empty collection.

**Proposal:** one validated network state for all consumers, with loading, errors,
refresh, last successful update, and stale data. Update GeoJSON without recreating
the map. **Acceptance:** empty feeds, null RSSI/battery, failed requests, stale
responses, changed nodes, and selection removal have predictable behavior; sample
and live data never silently mix. Use the configured API origin appropriate to
the site's separate hosting origin.

## WEB-05 — P2: sample labels conflict with deployed claims

**Inspected and visible in the browser.** The sample banner says no nodes are
deployed, while [NodeTypeGrid](../../src/components/build/NodeTypeGrid.tsx) counts
sample nodes as deployed. The sample deployment log also uses completed-event copy.

**Proposal:** propagate provenance consistently to cards, counters, logs, and map
titles. **Acceptance:** sample counts read as planned/sample; every surface that
can be viewed independently makes its provenance clear.

## WEB-06 — P2: public firmware license description contradicts artifacts

**Inspected.** [SITE](../../src/core/config/site.ts) says firmware is MIT; footer and
Terms use that value. The firmware repository LICENSE, bundled
[firmware license](../../public/licenses/meshtastic-firmware.txt), and NOTICE state
GPLv3. **Proposal:** describe website, backend, firmware, flasher, and hardware
licenses independently and reconcile visible copy with their license files.
**Acceptance:** footer, Terms, downloads, and notices identify the same actual
license for each artifact. This finding records a factual mismatch, not a legal opinion.

## WEB-07 — P2: blog URLs lack generated pages and individual metadata

**Inspected.** [githubPagesSpa.ts](../../config/build/githubPagesSpa.ts) excludes
parameterized routes, so article URLs rely on the GitHub Pages 404 shell and are
missing from the sitemap. [index.html](../../src/index.html) supplies shared social
metadata mentioning $70, while Home displays about $66. Changing document.title
does not generate article-specific HTML metadata.

**Proposal:** generate published slug pages and per-page title, description,
canonical, and social preview metadata. **Acceptance:** direct published article
requests have static files, article metadata, and sitemap entries; unknown URLs
retain the intended not-found behavior. Decide whether drafts are intentionally
public: current Blog and BlogPost show them with a Draft badge.

## WEB-08 — P2: route and article loading can be smaller

**Measured build output; recommendation.** [AppEntry](../../src/components/app/AppEntry.tsx)
imports all pages; [posts.ts](../../src/core/content/blog/posts.ts) eagerly loads all
article sources. Review build sizes before gzip were approximately 524 KB for
main JS, 1.02 MB for the MapLibre chunk, and 508 KB for its worker.

**Proposal:** load route features and individual article bodies when needed;
retain the existing lazy map boundary. **Acceptance:** measure entry bytes and
actual loading behavior before/after; direct navigation, recovery from failed
chunk downloads, and device chooser activation remain correct.

## WEB-09 — P2: node details can open outside the table user's viewport

**Inspected; UX recommendation.** [Map.tsx](../../src/components/pages/Map.tsx)
places NodePanel beside the map above the node table. A selection far down the
page can update an off-screen panel. **Proposal:** adjacent row details or a
visible desktop panel/mobile sheet. **Acceptance:** selecting a table node makes
its details discoverable, preserves focus, and provides accessible dismissal.

## WEB-10 — P2: small-text color pairs need contrast verification

**Token calculation, not a full accessibility audit.**
[color.css](../../src/assets/styles/tokens/color.css) gives approximately 4.24:1 for
text_3 on surface_2 and 3.93:1 for white on Bluetooth blue. The UI uses small xs/2xs
text. **Proposal:** strengthen affected color pairs and verify actual rendered
states. **Acceptance:** review labels, notes, buttons, hover/focus, disabled
states, keyboard flow, zoom, and reduced motion using automated and manual checks.

## WEB-11 — P2: shared controls recreate native semantics

**Recommendation requiring a convention decision.**
[Pressable](../../src/components/shared/primitives/Pressable.tsx) uses div controls;
[DataTable](../../src/components/shared/page/DataTable.tsx) recreates table semantics
with ARIA. This increases custom keyboard and accessibility maintenance.

Consider native buttons/tables inside shared components. Update AGENTS.md and
lint conventions if adopted; do not bypass the current rules piecemeal.
Acceptance includes keyboard behavior, focus, disabled behavior, link semantics,
and screen-reader table navigation without visual regressions.

## WEB-12 — P2: explain purpose and map capability before implementation detail

**UX recommendation.** Home leads with base-node price, which does not by itself
explain smoke measurements or the complete detection system. The map has no
geographic basemap and exposes VITE_BASEMAP_STYLE in visitor copy.

Lead with the research purpose and measured capability; distinguish base relay
cost from sensor-node cost. Consider optional schematic/geographic map views and
visitor-facing explanations. Name any tile provider in privacy documentation
before enabling it, as the current policy requires.

## WEB-13 — P1/P2: build guidance overstates current readiness

**Inspected.** Published presets enable radio transmission, power saving, and
disable Bluetooth, while firmware guidance defers transmission until private
channel provisioning and sleep until delivery/sampling tests (FW-01).
[bom.ts](../../src/core/content/build/bom.ts) also asks builders to print a shell
whose STL is marked unavailable.

**Proposal:** reconcile provisioning first (P1), then mark each build step and
download with its evidence/readiness (P2): bench-tested, available, experimental,
or pending. **Acceptance:** a builder can tell which path is executable today;
instructions do not imply available geometry or verified smoke detection;
presets and firmware agree on provisioning prerequisites.

## Regression and documentation maintenance

Prioritize WEB-01/02/03 regression cases before adding ordinary page snapshots.
Keep the route registry and reusable styles. Review structure warnings and
oversized modules by responsibility rather than splitting solely for line count.
Update stale source paths and one-line-live-switch claims in project.md during

fact-checked in this audit; the report addresses its integration and publication.
